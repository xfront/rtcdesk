# 2026-06-01 工作日志

## H.264 编解码链路重写（rtcdesk）

### 问题根因
- `host-service/src/encoder.rs` 输出 AVCC 格式（4字节大端长度前缀），但 webrtc-rs `TrackLocalStaticSample.write_sample()` 期望 Annex B 格式
- `client/src/muxer.rs` feed_nals 存 SPS/PPS 时用 `data[1..]` 跳过了 NAL header，导致 avcC box 的 profile_idc 字段读取错误
- `client/src/viewer.rs` spawn_track_handler 只调用 `cb.on_frame()`（OpenH264 软解路径），未接入 fMP4 muxer

### 修改内容

1. **host-service/src/encoder.rs**
   - `encode()` 改输出 Annex B（`00 00 00 01` 起始码），删除 AVCC 长度前缀逻辑
   - 改进：只有奇数维度时才做 pad_rgba 调用（避免不必要的内存分配）

2. **client/src/muxer.rs**
   - `feed_nals()` 修复：存 SPS/PPS 改为 `data.to_vec()`（包含 NAL header 字节）
   - `avcc_box()` 修复：profile_idc/constraint_flags/level_idc 从 `sps[1..3]` 读取（跳过 NAL header `sps[0]`）
   - 修复了 `feed_nals` 的 early-return 逻辑（`sps.is_some() && pps.is_some()` 而不是只检查 sps）

3. **client/src/viewer.rs**
   - `spawn_track_handler` 全面重写：改用 fMP4 muxer 路径（MSE 原生 H.264），废弃 OpenH264 软解路径
   - 新增 `detect_stream_params()` 函数：最小 SPS bit-level 解析，提取实际宽高
   - 新增 `BitReader` struct：Exp-Golomb 位读取器，用于 SPS 解析
   - fMP4 init segment 通过 `on_video_init` callback 发送，media segment 通过 `on_video_chunk` 发送

### 架构确认
视频路径：`RTP → H264Depacketizer（Annex B NAL） → Fmp4Muxer → base64 → JS MSE API → <video>元素`

## 架构级重写：放弃 fMP4+MSE，改用浏览器原生 WebRTC

### 背景
经过 5 轮 fMP4/MSE 调试均黑屏，用户明确要求架构变更：直接用浏览器 `RTCPeerConnection.ontrack` + `video.srcObject` 让浏览器原生解码 H.264。

### 核心变更

1. **client/src/viewer.rs** — 完全重写为信令客户端
   - 移除所有 webrtc-rs 依赖（PeerConnection、DataChannel、TrackRemote、H264Depacketizer）
   - 仅处理 WebSocket 信令（Offer/Answer SDP、ICE candidates）
   - 新增 `ViewerCallback` 方法：`on_sdp_offer()`、`on_ice_candidate()`、`on_data_channel_open()`
   - 新增 `send_clipboard_data_via_js()` 通过 JS DataChannel 发送剪贴板

2. **client/src/remote/viewer_loop.rs** — 完全重写事件循环
   - 移除 fMP4 通道/信号（video_init、video_chunk、frame_b64 等）
   - 新增 JS 轮询循环（100ms）：poll `window._rtcAnswerSDP`、`_rtcICECandidates`、`_rtcClipboardEvents`、`pc.connectionState`
   - `ConnectionStats` 增加 `serde::Deserialize` 用于从 JS stats JSON 反序列化
   - `document::eval()` 返回 `Eval`，需 `.await` 获取 `Result<serde_json::Value, EvalError>`

3. **client/src/remote/view.rs** — 完全重写 UI 层
   - 注入 JS `_rtcBridge` 对象：`handleOffer()`、`addIceCandidate()`、`sendInput()`、`sendClipboard()`、`close()`
   - `ontrack` → `video.srcObject = event.streams[0]`（浏览器原生 H.264 硬解）
   - `ondatachannel` → 区分 input/clipboard 通道，clipboard 解析 tag byte 推入 `_rtcClipboardEvents`
   - 鼠标/键盘事件：构建二进制 payload → base64 → `document::eval()` → JS DataChannel
   - `MouseData` 在 Dioxus 0.7 位于 `dioxus::html::events`，非 `input_data`
   - `MouseButton::Auxiliary` = 中键（非 `Middle`）

4. **删除的文件**
   - `client/src/muxer.rs` — fMP4 muxer（不再需要）
   - `client/src/decoder.rs` — OpenH264 软解（不再需要，浏览器硬解）

5. **client/Cargo.toml** — 移除 `webrtc`、`rtc`、`openh264` 依赖

### Dioxus 0.7 eval API 要点
- `document::eval(js)` 返回 `Eval`（非 `Result`）
- `.await` Eval 得到 `Result<serde_json::Value, EvalError>`
- 取字符串：`val.as_str()`（非 `res.as_string()`）
- 类型标注不支持 `if let Ok(x): Result<T, _>` → 改用 `serde_json::from_str::<T>(json)`

### 已知遗留问题
- 鼠标坐标映射：`send_mouse_via_js()` 直接发送 element 坐标，未做远程桌面坐标空间转换
- `mouse.rs` 中 `handle_mouse_event`/`relative_coords`/`logical_size` 等变成 dead code
- `InputCmd` enum 现在只用于 disconnect 命令，其余变体无人使用
