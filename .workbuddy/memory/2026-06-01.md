### 架构设计

#### `HostProcess`（`client/host_process.rs`）
- `spawn(host_id, password, stun, fps)` → 通过环境变量传递配置给 `rtcdesk-service`
  - `RTCDESK_ID` / `RTCDESK_PASSWORD` / `RTCDESK_STUN` / `RTCDESK_FPS`
  - 不设 `RTCDESK_ADDR`（使用 service 默认绑定 `0.0.0.0:9009`）
- `stop()` → `child.kill()` + `child.wait()` 回收僵尸进程
- `is_running()` → `child.try_wait()` 非阻塞检查
- `pid()` → 获取进程 PID
- `Drop` 自动 stop
- `find_service_binary()` 三级查找：同目录 → PATH → `target/{debug,release}/`
- `SharedHostProcess = Arc<Mutex<Option<HostProcess>>>`（`std::sync` 非 tokio，避免异步锁阻塞问题）

#### `HostCtx`（`client/components/host.rs`）
- `HostCtx { state: Signal<HostState>, proc: Signal<SharedHostProcess> }`
- 通过 `use_context_provider` 在 `app()` 层注入，跨 Tab 切换持久化
- 防止切换 Tab 时 `host_state` 和 `host_proc` 丢失导致进程泄漏

#### `HostTab` 组件
- 从 `use_context::<HostCtx>()` 获取共享状态
- 启动：`HostState::Starting` → `HostProcess::spawn()` → `Running` / `Error`
- 停止：`HostProcess::stop()` → `Stopped`
- `use_future` 每 3 秒轮询子进程健康状态，意外退出 → `Error("进程意外退出")`
- 运行中信息卡片显示：本机 IP:9009 + PID

## 双向文件剪贴板同步

### 需求
- 本地 Ctrl+C 文件 → 远程 Ctrl+V 粘贴文件到远程
- 远程 Ctrl+C 文件 → 本地 Ctrl+V 粘贴文件到本地

### 改动文件

#### `client/src/clipboard.rs` — 新增3个函数
- `get_clipboard_file_uris()` — 通过 xclip/wl-paste 读取 `text/uri-list` 格式的文件 URI
- `set_clipboard_file_uris()` — 通过 xclip/wl-copy 写入 `text/uri-list` 到剪贴板
- `parse_file_uris()` — 将 `file://` URI 字符串解析为 `Vec<PathBuf>`

#### `client/src/remote/viewer_loop.rs` — 双向文件剪贴板同步
- **Host→Viewer 接收端**：`on_clipboard_file_uris` 回调从只 log 改为调用 `set_clipboard_file_uris()` 设置本地剪贴板 + `record_received_file_uris()` 记录哈希
- **Viewer→Host 发送端**：`clip_poll` 在文本剪贴板检查之后，新增 `get_clipboard_file_uris()` 检查本地文件 URI → 解析路径 → 调用 `send_files_via_clipboard()` 发送
- **回声抑制**：新增 `CLIP_FILE_SYNC` 全局 Mutex 存储最近接收的文件 URI 哈希，`clip_poll` 检测到与接收相同的 URI 时跳过发送
- **提取公共函数**：`send_files_via_clipboard()` — 构建文件列表头+逐 chunk 发送+完成标记，避免 `file_send_rx` handler 和 `clip_poll` 的代码重复

### 数据流
1. **本地→远程**：本地文件浏览器 Ctrl+C → xclip `text/uri-list` → `clip_poll` 检测 → `parse_file_uris()` → `send_files_via_clipboard()` → clipboard DC → Host 接收+保存+xdotool Ctrl+V
2. **远程→本地**：Host 剪贴板文件 → Host `spawn_clipboard_writer` → clipboard DC → Viewer `viewer_clipboard_reader` → `on_clipboard_file_uris` → `set_clipboard_file_uris()` → 本地文件浏览器可 Ctrl+V

## 架构重构: WindowCmd 消息驱动的窗口控制

### 改动文件

## Bug 修复：远程控制工具栏全屏/最小化按钮失效

### 根因
`main.rs` 中 `window_cmd` 消费 effect 使用 `window_cmd.write().drain(..)` 来读取并清空命令队列。
在 Dioxus 0.7 中，`.write()` 不一定会注册 `use_effect` 的响应式订阅，导致推入命令后 effect 不重新执行。

### 修复
在 effect 开头添加显式 `window_cmd()` 读取（等价于 `.read()`），确保 effect 订阅信号变更：
```rust
use_effect(move || {
    if window_cmd().is_empty() { return; }  // 显式 read 订阅
    let cmds: Vec<WindowCmd> = window_cmd.write().drain(..).collect();
    ...
});
```

### 附带修复
- `.tb-icon-btn` 添加 `:hover` 和 `:active` 伪类样式，提供视觉反馈
